# Internationalization (i18n) Design — Russian + English

## Overview

Add per-user language selection (Russian/English) to both the Go bot and Next.js mini-app. Users pick their language on first `/start` or in settings. All user-facing text becomes translatable.

## Libraries

- **Bot (Go):** `nicksnyder/go-i18n/v2` — JSON translation files, `embed.FS`, per-request Localizer
- **Mini-app (Next.js):** `next-intl` v4 — cookie-based locale without i18n routing (no URL prefix)

## Language Storage

- `language TEXT DEFAULT 'ru'` column added to both `clients` and `trainers` tables
- `Language string` field on both models
- Supported values: `"ru"`, `"en"`

## Detection & Sync Flow

### First /start (Bot)

1. New user sends `/start`
2. Bot reads `msg.From.LanguageCode` from Telegram
3. If no DB record: show inline keyboard `🇷🇺 Русский | 🇬🇧 English`
4. User picks → language stored in DB on client/trainer creation
5. Welcome message sent in chosen language
6. Returning users skip language selection (already stored)

### Mini-App First Load (Zero Flash)

1. Bot generates mini-app URL with `?trainer=X&lang=ru` (reads stored language from DB)
2. Next.js middleware checks: no `locale` cookie + `?lang=` param present
3. Middleware sets `locale` cookie, redirects to same URL without `?lang=`
4. `i18n/request.ts` reads cookie → server renders in correct language immediately

### Cross-Device Sync

- On profile fetch (SWR), compare API `language` field vs current `locale` cookie
- If different → update cookie + `router.refresh()` (one-time, only on mismatch)

### Settings Change

1. User picks language in settings UI
2. API call `PATCH /api/profile` with `language` field → DB updated
3. Server action sets `locale` cookie
4. `router.refresh()` re-renders in new language

## Bot (Go) — go-i18n v2

### File Structure

```
bot/internal/i18n/
  i18n.go                    # Bundle init, Localizer factory, context helpers
  locales/
    active.ru.json           # ~150 Russian strings
    active.en.json           # ~150 English strings
```

### Translation File Format

```json
{
  "Booking.New": {
    "other": "New booking\n\nClient: {{.ClientName}}\nTime: {{.DateTime}}"
  },
  "Booking.Count": {
    "one": "{{.Count}} booking created",
    "few": "{{.Count}} bookings created",
    "many": "{{.Count}} bookings created",
    "other": "{{.Count}} bookings created"
  },
  "Btn.OpenApp": "Book"
}
```

Russian uses 4 CLDR plural forms: one, few, many, other.

### Core Module (`i18n.go`)

- `Init()` — loads bundle from `embed.FS`, called once in `main.go`
- `NewLocalizer(langs ...string)` — creates localizer for given language codes
- `L(ctx) *Localizer` — retrieves localizer from context, falls back to Russian
- `T(loc, messageID)` — simple string lookup
- `Tf(loc, messageID, data)` — lookup with template interpolation
- `Tp(loc, messageID, count, data)` — lookup with plural support

### Integration Points

- **Telegram handlers:** Create localizer from user's stored `Language` field (DB lookup)
- **API middleware:** Chi middleware reads authenticated user's language → stores localizer in context
- **Format functions:** All `FormatXxx(loc, ...)` functions receive `*i18n.Localizer` as first param
- **Notifications:** Always use **recipient's** language, not sender's
- **Master bot:** Uses Telegram's `language_code` for onboarding (no DB record yet)

### Message ID Convention

`Domain.Action` — e.g.:

- `Booking.New`, `Booking.Confirmed`, `Booking.Cancelled`
- `Recurring.Request`, `Recurring.Approved`
- `Error.NotFound`, `Error.Unauthorized`, `Error.Internal`
- `Btn.OpenApp`, `Btn.OpenAdmin`, `Btn.Confirm`, `Btn.Reject`
- `Master.Welcome`, `Master.TokenAccepted`

## Mini-App (Next.js) — next-intl

### File Structure

```
mini-app/
  messages/
    ru.json                  # ~350 strings, nested by namespace
    en.json                  # ~350 strings
  src/
    i18n/
      request.ts             # Cookie-based locale resolution
    middleware.ts             # Thin middleware: set locale cookie from ?lang= param
    actions/
      locale.ts              # Server action to set locale cookie
```

### next-intl Config (No i18n Routing)

- `next.config.ts`: wrap with `createNextIntlPlugin()`
- `i18n/request.ts`: reads `locale` cookie, imports `messages/${locale}.json`
- `layout.tsx`: `NextIntlClientProvider` with `locale` and `messages` props
- No `[locale]` folder, no `createMiddleware` from next-intl

### Middleware (`middleware.ts`)

Thin, custom middleware (~15 lines):

- If no `locale` cookie AND `?lang=` query param exists → set cookie, redirect without param
- Matcher: only pages that could have `?lang=` (root paths)
- Does NOT use next-intl's routing middleware

### Translation File Format

```json
{
  "HomePage": {
    "services": "Services",
    "location": "Location",
    "showMore": "Show more",
    "showLess": "Show less"
  },
  "BookingForm": {
    "selectDate": "Select date",
    "selectTime": "Select time",
    "noSlots": "No available slots",
    "comment": "Comment (optional)"
  },
  "Status": {
    "pending": "Pending",
    "confirmed": "Confirmed",
    "rejected": "Rejected",
    "cancelled": "Cancelled"
  },
  "Common": {
    "save": "Save",
    "saving": "Saving...",
    "cancel": "Cancel",
    "loading": "Loading..."
  }
}
```

### Key Namespaces

- `HomePage`, `BookingForm`, `BookingsPage`, `RecurringPage` — page-level
- `Status`, `Common`, `Navigation` — shared across pages
- `AdminDashboard`, `AdminSettings`, `AdminProfile`, `AdminSchedule`, `AdminServices`, `AdminDaysOff`, `AdminNotifications`, `AdminHelp` — admin pages
- `Dates` — month names (short/full), day names (short/full)
- `Duration` — hour/minute formatting
- `Errors` — toast error messages
- `Success` — toast success messages

### Component Usage

```tsx
"use client";
import { useTranslations } from "next-intl";

function StatusBadge({ status }: { status: string }) {
  const t = useTranslations("Status");
  return <span>{t(status)}</span>;
}
```

### Date/Number Formatting

- Replace hardcoded `"ru-RU"` in `toLocaleString()` with `useLocale()` from next-intl
- Centralize month/day name arrays into translation files under `Dates` namespace
- Duration formatting uses `Duration` namespace keys

### Language Selector Component

`LanguageSelector.tsx` — reusable, same button-group pattern as `ThemeSelector`:

- Displays `🇷🇺 RU | 🇬🇧 EN`
- On click: calls API to update DB + server action to set cookie + `router.refresh()`
- Placed in: client profile page (after theme selector), admin notifications page (after theme selector)

## API Changes

### Endpoints Modified

- `GET /api/profile` — include `language` in response
- `PATCH /api/profile` — accept `language` field
- `GET /api/admin/profile` — include `language` in response
- `PATCH /api/admin/profile` — accept `language` field
- All error responses — localized via `L(ctx)`

### New Behavior

- API middleware extracts user language from DB record → creates Localizer → stores in context
- Error helper functions use `L(ctx)` instead of hardcoded Russian strings
